## How to Use This Guide

This guide describes **what to build and how to verify it** — not the full source code. Each step tells you what a file should do, what classes and functions it should contain, and what behaviour to expect. Use this as prompt context for Claude Code to generate the actual implementations.

**Conventions:**

- `$` lines are terminal commands — run them in **Git Bash** on Windows
- **File description blocks** tell Claude Code what to generate: purpose, key classes/functions, and expected behaviour — not complete source
- Checklist items at the end of the phase must all pass before proceeding to Phase 2

## Goal

All tools installed and verified. Repository initialised with the correct structure. Shared Pydantic models defined. FastAPI main app and A2A server both start and respond to health checks. SQLite database initialised (single `claims.db` with both tables). Mock data fixtures written. `.env` in place with a working OpenRouter key.

**Estimated time:** 2–4 hours

### Step 1.1 — Install Python 3.12

Download from [https://python.org/downloads](https://python.org/downloads) — choose the **3.12.x Windows installer**. During installation, check **"Add Python to PATH"**.

Verify in Git Bash:

```bash
$ python --version       # expect Python 3.12.x
$ python -m pip --version
```

> **Git Bash note:** On Windows, use `python` not `python3`. If `python` is not found after installation, close and reopen Git Bash so the updated PATH is picked up.

### Step 1.9 — Create Shared Pydantic Models

**File:** `shared/__init__.py`

**Purpose:** Empty — marks `shared/` as a Python package.

---

**File:** `shared/models.py`

**Purpose:** All Pydantic models shared across processes. This is the single source of truth for data shapes — every agent, tool, and API endpoint that produces or consumes structured data references these models.

**Classes to define:**

`DenialRecord` — the structured output of Denial Intake. Fields: `claim_id` (str), `patient_name` (str), `patient_id` (str), `payer_id` (str), `payer_name` (str), `denial_reason_code` (str, e.g. `"CO-50"`), `denial_reason_text` (str), `is_clinical` (bool), `diagnosis_codes` (list of str, ICD-10), `date_of_service` (str, ISO date), `denial_date` (str, ISO date), `claim_amount` (float), `appeal_deadline` (str, ISO date), `days_remaining` (int), `worthiness_score` (int, 0–100), `recommendation` (literal: `proceed | close | skip`).

`ClinicalRecord` — a single patient record. Fields: `record_type` (literal: `admission_note | progress_note | discharge_summary | lab_result | imaging_report | prior_auth`), `content` (str), `date` (str, ISO date), `author` (optional str).

`GuidelineCitation` — a clinical guideline result. Fields: `diagnosis_code` (str), `guideline_source` (str, e.g. `"InterQual 2024"`), `criteria_summary` (str), `medical_necessity_indicators` (list of str), `confidence` (float, 0–1).

`EvidenceBundle` — output of the Clinical Evidence Agent. Fields: `claim_id` (str), `patient_records` (list of `ClinicalRecord`), `guideline_citations` (list of `GuidelineCitation`), `lcd_policy_text` (optional str), `sufficiency_reasoning` (str), `partial` (bool, default `False` — set to `True` when human chose to proceed with incomplete evidence).

`AppealLetter` — output of Appeal Writer. Fields: `claim_id` (str), `payer_id` (str), `payer_name` (str), `letter_text` (str), `submission_format` (str), `required_attachments` (list of str), `drafted_at` (str, ISO datetime).

`PhysicianReview` — output of Physician Sign-off. Fields: `claim_id` (str), `physician_required` (bool), `review_status` (literal: `approved | flagged | bypassed`), `notes` (optional str).

`SubmissionConfirmation` — final output of Submission Agent. Fields: `claim_id` (str), `confirmation_number` (str), `submitted_at` (str, ISO datetime), `submission_method` (str), `payer_id` (str).

---

**File:** `shared/events.py`

**Purpose:** SSE event schema and valid step names. Defines the `WorkflowEvent` Pydantic model emitted over the SSE stream, and the `WorkflowStep` string enum of all valid step values.

**Classes to define:**

`WorkflowStep` — string enum. Values: `intake_complete`, `evidence_gathering`, `evidence_gathered`, `evidence_gathered_partial`, `human_review_required`, `hitl_response_received`, `letter_drafted`, `physician_reviewed`, `appeal_submitted`, `case_closed`, `error`.

`WorkflowEvent` — Pydantic model. Fields: `claim_id` (str), `step` (WorkflowStep), `status` (literal: `success | warning | error | waiting`), `message` (str), `timestamp` (str, ISO datetime, auto-populated), `payload` (dict, default empty).

---

**File:** `shared/llm.py`

**Purpose:** Single place to create OpenRouter-backed LLM clients. Reads from environment variables so model selection is configurable without code changes.

**Functions to define:**

`get_agent_llm() -> tuple[OpenAI, str]` — returns an `openai.OpenAI` client pointed at `https://openrouter.ai/api/v1` and the agent model string from `OPENROUTER_AGENT_MODEL`. Used by agent tools that do LLM reasoning (evaluate sufficiency, draft letter).

`get_crewai_llm_string() -> str` — returns the LiteLLM-formatted model string for CrewAI agent definitions, e.g. `"openrouter/openai/gpt-5-mini"`. CrewAI uses LiteLLM internally and needs this prefix format.

### Step 1.11 — Create the Database Initialisation Script

**File:** `shared/db.py`

**Purpose:** Creates the single SQLite database (`claims.db`) with both tables if they don't already exist. Called at startup by both the main app and the MCP server. Safe to call multiple times (uses `CREATE TABLE IF NOT EXISTS`).

**Functions to define:**

`init_db(db_path: str = "data/claims.db") -> None` — creates `data/` directory if needed, opens/creates `claims.db`, executes DDL for both tables:

Table `appeals`: columns `id` (TEXT PRIMARY KEY), `status` (TEXT NOT NULL), `denial_record` (TEXT — JSON blob), `evidence_bundle` (TEXT — JSON blob), `appeal_letter` (TEXT), `submission` (TEXT — JSON blob), `created_at` (DATETIME DEFAULT CURRENT_TIMESTAMP), `updated_at` (DATETIME DEFAULT CURRENT_TIMESTAMP).

Table `appeal_events`: columns `id` (TEXT PRIMARY KEY — UUID), `claim_id` (TEXT NOT NULL), `event_type` (TEXT NOT NULL), `agent_name` (TEXT), `payload` (TEXT — JSON blob), `created_at` (DATETIME DEFAULT CURRENT_TIMESTAMP).

`seed_db(db_path: str = "data/claims.db") -> None` — inserts the two test claim records (`CLM-2026-00123`, `CLM-2026-00199`) into the `appeals` table with status `pending` if they don't already exist. Reads the denial EOB JSON from `data/mock_eobs/` and stores in the `denial_record` column.

`get_connection(db_path: str = "data/claims.db") -> sqlite3.Connection` — returns an open connection with `row_factory = sqlite3.Row` set. Callers are responsible for closing.

### Step 1.12 — Create the Main FastAPI App Skeleton

**File:** `main.py`

**Purpose:** The primary FastAPI application. Entry point for the browser UI. Manages the SSE event queue, kicks off the CrewAI crew asynchronously, and exposes the HITL resume endpoint. In Phase 1 this is a skeleton — all endpoints exist and respond, but crew execution is stubbed.

**Key components to define:**

`app = FastAPI(title="Claim Reversal")` — application instance. Include CORS middleware allowing all origins (needed for `file://` browser access).

`event_queues: dict[str, asyncio.Queue]` — module-level dict mapping `claim_id` to its SSE queue. The crew runner puts events here; the SSE endpoint reads from here.

`async def emit_event(claim_id: str, event: WorkflowEvent) -> None` — puts a serialised event onto the queue for `claim_id`. Creates the queue if it doesn't exist yet.

`POST /appeal` — accepts `{"claim_id": str}` body. Validates the claim ID exists in `claims.db`. Creates a queue entry. Launches `run_crew(claim_id)` as a background task. Returns `{"claim_id": claim_id, "status": "started"}`.

`GET /stream/{claim_id}` — SSE endpoint. Returns a `StreamingResponse` with `media_type="text/event-stream"`. Reads from `event_queues[claim_id]` in a loop, yielding `event: workflow_step\ndata: {json}\n\n` for each event. Emits heartbeat every 30s during idle. Terminates when it receives a terminal step (`case_closed`, `appeal_submitted`, `error`).

`POST /appeal/{claim_id}/resume` — HITL resume endpoint. Accepts `{"choice": "proceed" | "close"}`. In Phase 1: returns `{"status": "not_implemented_yet"}`. Will be fully wired in Phase 4.

`GET /health` — returns `{"status": "ok", "service": "main-app"}`.

`async def run_crew(claim_id: str) -> None` — stub in Phase 1. Emits a sequence of fake `WorkflowEvent`s with 1-second delays to simulate the crew running (intake_complete, evidence_gathering, evidence_gathered, letter_drafted, physician_reviewed, appeal_submitted). In Phase 4 this becomes the real crew kickoff.

On startup (`@app.on_event("startup")` or lifespan): call `init_db()` and `seed_db()`.

**File:** `crew/appeal_crew.py`

**Purpose:** The crew runner that orchestrates the full appeal pipeline.
