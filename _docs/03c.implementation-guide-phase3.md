## Goal

The Clinical Evidence Agent runs as a standalone LangGraph-powered A2A server on port 8001. The graph implements the full evidence-gathering loop: fetch records → lookup guidelines → fetch LCD (no-op) → evaluate sufficiency → retry or escalate. The `interrupt()` HITL mechanism suspends the graph when retries are exhausted, and resumes when a human choice is provided. The A2A server exposes a task-based interface that the crew runner will consume in Phase 4.

After Phase 3:
- The LangGraph graph runs end-to-end for both variants (sufficient and insufficient)
- The A2A server accepts `tasks/send` requests and returns proper status responses
- HITL suspend/resume works via `interrupt()` and `Command(resume=...)`
- The graph calls MCP tools via MCP client protocol (SSE transport to :8002)
- LangGraph nodes that call MCP tools are async

**Estimated time:** 4–6 hours

### Step 3.1 — Implement the LangGraph Graph

**File:** `a2a_server/graph.py`

**Purpose:** Defines the LangGraph `StateGraph` for the Clinical Evidence Agent. Contains all graph nodes, conditional edge functions, and the compiled graph instance.

**Imports needed:**
- `langgraph.graph.StateGraph`, `START`, `END`
- `langgraph.types.interrupt`, `langgraph.types.Command`
- `langgraph.checkpoint.memory.MemorySaver`
- `a2a_server.state.AppealState`, `EvidenceSufficiency`, `HumanChoice`
- Local tool functions from `a2a_server/tools/` (fetch_records, evaluate_sufficiency, fetch_lcd_policy)
- `shared.mcp_client.McpClient` — for MCP tool calls (lookup_guideline, log_appeal_event)
- `shared.models.ClinicalRecord`, `GuidelineCitation`, `EvidenceBundle`

**MCP client setup:**

The graph module holds a module-level `McpClient` instance (from `shared/mcp_client.py`) that connects to `http://localhost:8002/sse`. It is initialized at import time or lazily on first use. LangGraph nodes that call MCP tools are defined as `async` functions.

**Node functions to define (each takes `state: AppealState` and returns a partial state dict):**

1. `fetch_records(state) -> dict` — (sync) calls `fetch_patient_records(claim_id, date_of_service, include_supplemental)`. Note: `date_of_service` is not in `AppealState` — derive it by reading the denial record from the DB (query `appeals` table for `claim_id`, parse `denial_record` JSON to get `date_of_service`). Returns `{"patient_records": [record.model_dump() for record in records]}`.

2. `async lookup_guideline(state) -> dict` — (async) iterates over `state["diagnosis_codes"]`, calls `await mcp_client.lookup_clinical_guideline(code)` for each. Returns `{"guideline_citations": [list of guideline dicts]}`.

3. `fetch_lcd(state) -> dict` — (sync) calls `fetch_lcd_policy(state["diagnosis_codes"][0])`. Returns `{"lcd_policy_text": result["policy_text"]}`.

4. `evaluate_sufficiency(state) -> dict` — (sync) reconstructs `ClinicalRecord` and `GuidelineCitation` objects from state dicts, calls `evaluate_evidence_sufficiency(records, citations, diagnosis_codes)`. Returns `{"sufficiency": result["sufficiency"], "sufficiency_reasoning": result["reasoning"]}`.

5. `increment_retry(state) -> dict` — returns `{"retry_count": state["retry_count"] + 1, "include_supplemental": True}`. Note: `include_supplemental` is already declared in `a2a_server/state.py` (added in Phase 1). The `fetch_records` node reads this flag to decide whether to include supplemental records.

6. `human_review_interrupt(state) -> dict` — calls `interrupt()` with a payload dict: `{"claim_id": state["claim_id"], "sufficiency_reasoning": state["sufficiency_reasoning"], "evidence_gathered": {"record_count": len(state["patient_records"] or []), "guideline_count": len(state["guideline_citations"] or [])}, "options": ["proceed", "close"]}`. The return value of `interrupt()` is the human's choice dict. Sets `human_choice` from the returned value. Returns `{"hitl_triggered": True, "human_choice": choice["choice"]}`.

7. `build_bundle(state) -> dict` — assembles an `EvidenceBundle` from state. Sets `partial=False`. Returns `{"evidence_bundle": bundle.model_dump()}`.

8. `build_bundle_partial(state) -> dict` — same as `build_bundle` but sets `partial=True`. Returns `{"evidence_bundle": bundle.model_dump()}`.

9. `close_case(state) -> dict` — returns `{"closed_reason": "insufficient_evidence_human_closed"}`.

**Conditional edge functions:**

```python
def route_after_evaluation(state: AppealState) -> str:
    if state["sufficiency"] == EvidenceSufficiency.SUFFICIENT:
        return "build_bundle"
    elif state["retry_count"] >= 2:
        return "human_review_interrupt"
    else:
        return "increment_retry"

def route_after_hitl(state: AppealState) -> str:
    if state["human_choice"] == HumanChoice.PROCEED:
        return "build_bundle_partial"
    return "close_case"
```

**Graph assembly:**

```python
builder = StateGraph(AppealState)

# Add all nodes
builder.add_node("fetch_records", fetch_records)
builder.add_node("lookup_guideline", lookup_guideline)
builder.add_node("fetch_lcd", fetch_lcd)
builder.add_node("evaluate_sufficiency", evaluate_sufficiency)
builder.add_node("increment_retry", increment_retry)
builder.add_node("human_review_interrupt", human_review_interrupt)
builder.add_node("build_bundle", build_bundle)
builder.add_node("build_bundle_partial", build_bundle_partial)
builder.add_node("close_case", close_case)

# Linear edges
builder.add_edge(START, "fetch_records")
builder.add_edge("fetch_records", "lookup_guideline")
builder.add_edge("lookup_guideline", "fetch_lcd")
builder.add_edge("fetch_lcd", "evaluate_sufficiency")

# Conditional: after evaluation
builder.add_conditional_edges("evaluate_sufficiency", route_after_evaluation)

# Retry loops back
builder.add_edge("increment_retry", "fetch_records")

# Conditional: after HITL
builder.add_conditional_edges("human_review_interrupt", route_after_hitl)

# Terminal edges
builder.add_edge("build_bundle", END)
builder.add_edge("build_bundle_partial", END)
builder.add_edge("close_case", END)
```

**Compiled graph:**

```python
checkpointer = MemorySaver()
graph = builder.compile(checkpointer=checkpointer)
```

The `checkpointer` enables `interrupt()` to suspend and resume. The `thread_id` passed in config at invocation time determines which checkpoint to resume from.

**Async invocation:** Since `lookup_guideline` is async, use `await graph.ainvoke(...)` instead of `graph.invoke(...)` in the A2A server endpoint. LangGraph handles mixed sync/async nodes — sync nodes run in a thread pool automatically.

### Step 3.2 — Update the A2A Server to Invoke the Graph

**File:** `a2a_server/app.py` — replace Phase 1 stub.

**Purpose:** The A2A server receives task requests, invokes the LangGraph graph, and returns appropriate status responses. Handles both initial invocation and resume-after-HITL.

**Key additions:**

Add `sys.path` fix at the top (same pattern as `mcp_server/server.py`) so imports resolve when run as `uvicorn a2a_server.app:app`.

Import `graph` and `checkpointer` from `a2a_server.graph`. Import `Command` from `langgraph.types`.

**POST `/a2a` endpoint — full implementation:**

Accepts a JSON body with this shape:
```json
{
  "id": "optional-task-id",
  "messages": [{"role": "user", "parts": [{"type": "data", "data": {...}}]}]
}
```

Logic:
1. Extract the `data` payload from the first message's first part.
2. Check if the request includes an existing `id` AND `data` contains `human_choice` — this means it's a **resume** request.
3. **If new task** (no `id` or no `human_choice`):
   - Generate a `task_id` (use `uuid4`).
   - Build initial `AppealState` from the data payload: `claim_id`, `diagnosis_codes`, `payer_id`, `denial_reason_code`, plus defaults: `retry_count=0`, `include_supplemental=False`, `hitl_triggered=False`, all Optional fields as `None`.
   - Invoke the graph: `result = await graph.ainvoke(initial_state, config={"configurable": {"thread_id": task_id}})`.
   - After invoke returns, **inspect the result** to determine if the graph completed or suspended (see detection logic below).
   - If completed: return `status: "completed"` response.
   - If suspended: return `status: "input-required"` response.
4. **If resume** (has `id` and `human_choice`):
   - Use the provided `id` as the `task_id` / `thread_id`.
   - Call `await graph.ainvoke(Command(resume={"choice": data["human_choice"]}), config={"configurable": {"thread_id": task_id}})`.
   - Return `status: "completed"` with the result.

**Suspension detection**: `graph.invoke()` with a checkpointer does **NOT** raise `GraphInterrupt` — it returns normally. Do not use try/except for this. Instead, inspect the returned state:
- If `result.get("evidence_bundle")` is not None OR `result.get("closed_reason")` is not None → graph **completed**.
- If `result.get("hitl_triggered") == True` and `result.get("evidence_bundle") is None` → graph is **suspended** at interrupt.

Alternatively, use `graph.get_state(config)` after invoke — if `state.next` is non-empty, the graph is suspended.

**Response shapes:**

Completed (evidence found):
```json
{
  "id": "<task_id>",
  "status": {"state": "completed"},
  "messages": [{"role": "agent", "parts": [{"type": "data", "data": {"evidence_bundle": {...}}}]}]
}
```

Completed (case closed):
```json
{
  "id": "<task_id>",
  "status": {"state": "completed"},
  "messages": [{"role": "agent", "parts": [{"type": "data", "data": {"closed_reason": "..."}}]}]
}
```

Input required (HITL):
```json
{
  "id": "<task_id>",
  "status": {"state": "input-required"},
  "messages": [{"role": "agent", "parts": [{"type": "data", "data": {
    "claim_id": "...",
    "sufficiency_reasoning": "...",
    "evidence_gathered": {"record_count": 3, "guideline_count": 1},
    "options": ["proceed", "close"]
  }}]}]
}
```

**Keep existing endpoints:** `GET /.well-known/agent-card.json` and `GET /health` remain unchanged.

### Step 3.3 — Handle the `date_of_service` Lookup

**Problem:** `AppealState` doesn't include `date_of_service` (it's not part of the denial reason info passed from the crew runner), but `fetch_patient_records` needs it.

**Solution:** The `fetch_records` node reads it from the database. Add a helper in `a2a_server/graph.py`:

```python
def _get_date_of_service(claim_id: str) -> str:
    """Reads date_of_service from the appeals table denial_record JSON."""
    conn = get_connection()
    try:
        row = conn.execute("SELECT denial_record FROM appeals WHERE id = ?", (claim_id,)).fetchone()
        if row and row["denial_record"]:
            return json.loads(row["denial_record"]).get("date_of_service", "")
        return ""
    finally:
        conn.close()
```

The `fetch_records` node calls this to get `date_of_service` before calling the tool.

## Design Notes for the Implementer

**Why `interrupt()` return value vs. `Command(resume=...)`:**

LangGraph's `interrupt()` works differently depending on the version. In `langgraph >= 1.2`:
- `interrupt(payload)` suspends the graph and the payload is surfaced to the caller.
- When resumed via `graph.invoke(Command(resume=value), config=...)`, the `interrupt()` call **returns** the `value` that was passed in `Command(resume=...)`.
- This means `human_review_interrupt` can do: `choice = interrupt(payload)` and then set state from `choice`.

**Checkpointer scope:**

`MemorySaver` is in-memory only. If the A2A server process restarts, all suspended graphs are lost. This is acceptable for a learning project. Production would use `SqliteSaver` or `PostgresSaver`.

**MCP tool access pattern:**

The graph calls MCP tools via the MCP client protocol (`shared/mcp_client.py`), connecting to the MCP server on :8002 over SSE transport. This means the MCP server must be running before the A2A server starts. The `McpClient` class handles connection retry with backoff to accommodate startup ordering.

Nodes that call MCP tools (`lookup_guideline`) are defined as `async` functions. LangGraph supports mixed sync/async nodes — sync nodes (like `fetch_records`, `evaluate_sufficiency`) are automatically run in a thread pool. The graph is invoked with `await graph.ainvoke(...)` from the async A2A server endpoint.

Local tools (`fetch_patient_records`, `evaluate_evidence_sufficiency`, `fetch_lcd_policy`) remain direct Python imports within the A2A server process since they are local to that service, not shared MCP tools.

**Thread ID strategy:**

The A2A server generates `task_id` on initial request and uses it as both the A2A task correlation ID and the LangGraph `thread_id`. On resume, the caller passes back the same `id`, which the server uses to locate the checkpointed graph state.
