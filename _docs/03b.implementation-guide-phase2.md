# Claim Denied — Implementation Guide
## Phase 2: Tool Implementations & MCP Server
*Companion to Technical Specification v0.3*

---

## How to Use This Guide

This guide describes **what to build and how to verify it** — not the full source code. Each step tells you what a file should do, what classes and functions it should contain, and what behaviour to expect. Use this as prompt context for Claude Code to generate the actual implementations.

**Conventions:**

- `$` lines are terminal commands — run them in **Git Bash** on Windows
- **File description blocks** tell Claude Code what to generate: purpose, key classes/functions, and expected behaviour — not complete source
- Checklist items at the end of the phase must all pass before proceeding to Phase 3

**Prerequisite:** Phase 1 complete and verified (see `03a.implementation-guide-phase1.md`).

---

## Goal

Every tool in the system has a real implementation backed by hardcoded mock data. All tools are individually callable and testable with correct Pydantic schemas. The MCP server runs with real tool handlers. After Phase 2, running any single tool produces a plausible, schema-valid response.

**Estimated time:** 3–5 hours

### Step 2.1 — Implement the Triage Denial Tool (Collapsed)

**File:** `tools/triage_denial.py`

**Purpose:** Single tool that replaces the previous 4-tool intake pipeline. Accepts structured denial input, returns classification, deadline status, and worthiness score in one call.

**Function to define:**

`triage_denial(claim_id: str, denial_reason_code: str, claim_amount: float, payer_id: str, date_of_service: str, denial_date: str) -> dict` — performs all intake logic in one call:

1. **Classify denial**: Hardcoded mapping. Clinical codes: `CO-50` (not medically necessary), `CO-97` (payment included in other service), `CO-167` (diagnosis not covered). Administrative codes: `CO-4` (service not authorized), `CO-16` (claim lacks information), `CO-22` (coordination of benefits). Unknown codes default to `administrative`.

2. **Check deadline**: Looks up payer's appeal window in a hardcoded dict (BCBS: 90 days, Aetna: 60 days, UHC: 180 days, Cigna: 90 days, Humana: 60 days, default: 90 days). Computes `appeal_deadline` (ISO date string) and `days_remaining` (int). `is_open` is `True` if `days_remaining > 0`.

3. **Score worthiness**: Base score 0. Add 40 if `claim_amount >= 5000`, 30 if `>= 1000`, 10 if `>= 500`. Add 30 if denial is clinical. Subtract 20 if `days_remaining < 14`. Subtract 15 if `get_claim_history()` shows a prior appeal for the same denial reason code was already denied (call `get_claim_history` from `mcp_server/tools/claim_history.py` directly). `recommendation` is `proceed` if score >= 50, else `close`.

**Returns:** `{"is_clinical": bool, "denial_type": str, "description": str, "appeal_deadline": str, "days_remaining": int, "is_open": bool, "worthiness_score": int, "recommendation": "proceed" | "close", "reasoning": str}`

### Step 2.2 — Implement the Draft Appeal Letter Tool (Collapsed)

**File:** `tools/draft_letter.py`

**Purpose:** Single tool that composes AND formats the appeal letter. Replaces the previous `draft_letter.py` + `format_letter.py` split.

**Function to define:**

`draft_appeal_letter(denial_record: DenialRecord, evidence_bundle: EvidenceBundle, payer_rules: dict) -> AppealLetter` — calls `get_agent_llm()`. Constructs a prompt containing: the denial reason, payer name, date of service, patient diagnosis codes, patient records summary, guideline citations, whether evidence is partial, and payer-specific required sections from `payer_rules`. Instructs the LLM to write a formal medical appeal letter with payer-appropriate formatting including: header block (payer address, submission reference), patient identification, denial reference, statement of medical necessity, clinical evidence summary, guideline citations, and closing request for reconsideration. Returns an `AppealLetter` model instance.

### Step 2.3 — Implement the Physician Review Tool (Collapsed)

**File:** `tools/physician_review.py`

**Purpose:** Single tool that determines if physician attestation is required AND simulates the review. Replaces the previous `physician_check.py` with its two functions.

**Function to define:**

`physician_review(claim_id: str, denial_type: str, claim_amount: float, payer_id: str, letter_text: str) -> PhysicianReview` — performs both steps:

1. **Check if required**: Physician is required if `denial_type == "clinical"` AND (`claim_amount >= 10000` OR `payer_id` is one of `["BCBS", "UHC"]`). If not required, return immediately with `review_status="bypassed"`.

2. **Simulate review** (if required): Always returns `review_status="approved"`. This is a simulated step — no real HITL, no failure path.

**Returns:** `PhysicianReview` model instance.

### Step 2.4 — Implement the Submit Appeal Tool

**File:** `tools/submit_appeal.py`

**Purpose:** Simulates submitting the appeal to the payer.

**Function to define:**

`submit_appeal(claim_id: str, payer_id: str, letter_text: str) -> SubmissionConfirmation` — generates a confirmation number (`f"CONF-{payer_id[:3].upper()}-{uuid4().hex[:8].upper()}"`). Updates the appeal's status to `submitted` in `claims.db`. Returns a `SubmissionConfirmation` model instance with the confirmation number, current timestamp, and submission method (looked up from payer rules).

### Step 2.5 — Implement Evidence Agent Local Tools

**File:** `a2a_server/tools/fetch_records.py`

**Purpose:** Returns clinical records for a claim from the hardcoded mock fixtures.

**Function to define:**

`fetch_patient_records(claim_id: str, date_of_service: str, include_supplemental: bool = False) -> list[ClinicalRecord]` — reads `data/mock_records/{claim_id}.json`. Constructs `ClinicalRecord` objects from each entry in the `records` array. When `include_supplemental=True`, also includes entries from the `supplemental_records` array in the same file (1–2 additional records, e.g. specialist consult, additional imaging). Returns the combined list. If file not found, returns an empty list.

> Note: CLM-2024-00123 has 6 records (sufficient on first try — supplemental not needed). CLM-2024-00199 has 1 record in `records` + 2 in `supplemental_records` (still insufficient after retry with supplemental — triggers HITL).

---

**File:** `a2a_server/tools/evaluate_sufficiency.py`

**Purpose:** Scores whether the gathered evidence is sufficient to support a medical necessity argument.

**Function to define:**

`evaluate_evidence_sufficiency(patient_records: list[ClinicalRecord], guideline_citations: list[GuidelineCitation], diagnosis_codes: list[str]) -> dict` — calls `get_agent_llm()`. Prompt contains: the records content, the guideline criteria, and the diagnosis codes. Asks the LLM to score sufficiency on a scale 0–10 and explain reasoning. Returns `{"sufficiency": EvidenceSufficiency, "reasoning": str, "score": float}`. Map score >= 6 to `SUFFICIENT`, < 6 to `INSUFFICIENT`. The LLM prompt must specify: return only valid JSON with keys `score` (float), `reasoning` (str).

---

**File:** `a2a_server/tools/fetch_lcd_policy.py`

**Purpose:** Returns LCD policy text. Mock implementation now; Playwright in stretch goal.

**Function to define:**

`fetch_lcd_policy(diagnosis_code: str) -> dict` — checks environment variable `USE_PLAYWRIGHT`. If `false` (default): returns `{"policy_text": "", "source_url": ""}` (no-op — graph treats empty string as no LCD data available). If `true`: delegates to Playwright implementation (stretch goal).

### Step 2.6 — Implement MCP Server Tools

**File:** `mcp_server/tools/lookup_guideline.py`

**Purpose:** Returns clinical guideline criteria for a diagnosis code. Hardcoded for 2 ICD-10 codes.

**Function to define:**

`lookup_clinical_guideline(diagnosis_code: str) -> dict` — returns from a hardcoded dict:

For `J18.9` (pneumonia): `{"diagnosis_code": "J18.9", "guideline_source": "InterQual 2024 — Acute Care", "criteria_summary": "Inpatient admission for community-acquired pneumonia is appropriate when: (1) oxygen saturation < 92% on room air, (2) CURB-65 score >= 2, (3) IV antibiotics required, or (4) significant comorbidities precluding outpatient management.", "medical_necessity_indicators": ["hypoxia requiring supplemental O2", "CURB-65 >= 2", "IV antibiotic therapy", "hemodynamic instability", "failure of outpatient therapy"], "confidence": 0.92}`

For `M17.11` (knee OA): `{"diagnosis_code": "M17.11", "guideline_source": "MCG 27th Edition — Surgical Care", "criteria_summary": "Total knee arthroplasty is appropriate when: (1) radiographic evidence of Grade III-IV OA, (2) failure of at least 3 months of conservative treatment including PT, NSAIDs, and injections, (3) documented functional limitation (unable to walk > 2 blocks), and (4) BMI < 40 or optimization plan documented.", "medical_necessity_indicators": ["radiographic OA Grade III-IV", "failed conservative treatment >= 3 months", "functional limitation documented", "PT trial completed", "BMI optimization if applicable"], "confidence": 0.85}`

For unknown codes: return a generic response with `"guideline_source": "No specific guideline found"` and empty indicators.

---

**File:** `mcp_server/tools/payer_rules.py`

**Purpose:** Returns payer-specific appeal rules. Fully hardcoded.

**Function to define:**

`get_payer_appeal_rules(payer_id: str) -> dict` — returns from a hardcoded dict keyed by payer ID:

- `BCBS`: 90-day window, portal submission, required sections: ["Patient Demographics", "Denial Reference", "Clinical Summary", "Medical Necessity Argument", "Supporting Documentation List", "Physician Attestation"]
- `AETNA`: 60-day window, fax or mail, required sections: ["Member Information", "Claim Reference", "Clinical Rationale", "Evidence Summary", "Conclusion"]
- `UHC`: 180-day window, portal only, required sections: ["Member ID and Claim Number", "Date of Service", "Denial Reason Response", "Clinical Evidence", "Guideline Citations", "Medical Necessity Statement", "Provider Signature"]
- `CIGNA`: 90-day window, fax or portal, required sections: ["Patient Info", "Claim Details", "Clinical Argument", "Attached Documentation", "Guideline References", "Provider Contact"]
- `HUMANA`: 60-day window, mail only, required sections: ["Beneficiary Information", "Service Details", "Medical Necessity Justification", "Clinical Documentation Summary", "Requesting Provider Signature"]

Default fallback for unknown payer IDs: 90-day window, fax, generic 4 required sections.

Each entry also includes `payer_name` and `contact_address`.

---

**File:** `mcp_server/tools/audit_log.py`

**Purpose:** Writes appeal events to the `appeal_events` table in `claims.db`.

**Function to define:**

`log_appeal_event(claim_id: str, event_type: str, payload: dict, agent_name: str) -> dict` — generates a UUID for `event_id`. Opens connection via `get_connection()`. Inserts a row with all fields. Returns `{"event_id": str, "timestamp": str}`.

---

**File:** `mcp_server/tools/claim_history.py`

**Purpose:** Retrieves prior denial and appeal history for a claim from `claims.db`.

**Function to define:**

`get_claim_history(claim_id: str) -> dict` — opens connection via `get_connection()`. Queries the `appeals` table for the row matching `claim_id`. Returns `{"claim_id": str, "status": str, "prior_denials": list, "prior_appeals": list, "last_payment": dict | None}`. If not found: returns same shape with empty lists and `status = "not_found"`.

### Step 2.8 — Write Phase 2 Tests

**File:** `tests/__init__.py` — empty.

**File:** `tests/test_tools.py`

**Purpose:** Unit tests for every tool function, called directly (no running services needed). All tests use hardcoded mock data fixtures.

**Test cases to implement:**

1. `test_triage_denial_clinical_proceed` — call `triage_denial("CLM-2024-00123", "CO-50", 12400.0, "HUMANA", "2024-10-01", "2024-10-18")`; assert `is_clinical == True`, `recommendation == "proceed"`, `worthiness_score >= 70`.

2. `test_triage_denial_administrative` — call with `denial_reason_code="CO-4"`; assert `is_clinical == False`, `denial_type == "administrative"`.

3. `test_triage_denial_deadline_closed` — call with `denial_date` 100 days ago and `payer_id="AETNA"` (60-day window); assert `is_open == False` and `days_remaining < 0`.

4. `test_triage_denial_low_worthiness` — call with `claim_amount=200.0`; assert `recommendation == "close"`.

5. `test_triage_denial_unknown_code` — call with `denial_reason_code="CO-9999"`; assert no exception; assert `is_clinical == False`.

6. `test_fetch_patient_records_sufficient` — call `fetch_patient_records("CLM-2024-00123", "2024-10-01")`; assert result has >= 3 records; verify `ClinicalRecord` fields.

7. `test_fetch_patient_records_sparse` — call for `CLM-2024-00199` with `include_supplemental=False`; assert result has exactly 1 record.

7b. `test_fetch_patient_records_supplemental` — call for `CLM-2024-00199` with `include_supplemental=True`; assert result has 3 records (1 base + 2 supplemental).

8. `test_fetch_patient_records_not_found` — call for `CLM-NONEXISTENT`; assert returns empty list (no exception).

9. `test_fetch_lcd_policy_mock` — call `fetch_lcd_policy("J18.9")`; assert `policy_text == ""` and `source_url == ""` (no-op when `USE_PLAYWRIGHT=false`).

10. `test_lookup_guideline_j189` — call `lookup_clinical_guideline("J18.9")`; assert `guideline_source` contains "InterQual" and `medical_necessity_indicators` is non-empty.

11. `test_lookup_guideline_m1711` — call for `M17.11`; assert `guideline_source` contains "MCG".

12. `test_lookup_guideline_unknown` — call for `X99.99`; assert no exception; returns response with empty indicators.

13. `test_payer_rules_bcbs` — call `get_payer_appeal_rules("BCBS")`; assert `appeal_window_days == 90` and `required_sections` has 6 items.

14. `test_payer_rules_unknown` — call for `"XYZ_UNKNOWN"`; assert no exception; assert fallback response.

15. `test_log_appeal_event` — call `log_appeal_event("CLM-2024-00123", "test_event", {"key": "value"}, "test_agent")`; assert returned `event_id` is non-empty; query DB directly and confirm row exists.

16. `test_get_claim_history_found` — call `get_claim_history("CLM-2024-00123")`; assert `status != "not_found"`.

17. `test_get_claim_history_not_found` — call `get_claim_history("CLM-NONEXISTENT")`; assert `status == "not_found"`.

18. `test_physician_review_required_high_value` — call `physician_review("CLM-2024-00123", "clinical", 15000.0, "BCBS", "...")`; assert `physician_required == True` and `review_status == "approved"`.

19. `test_physician_review_not_required` — call with `claim_amount=800.0, payer_id="AETNA"`; assert `physician_required == False` and `review_status == "bypassed"`.

20. `test_submit_appeal` — call `submit_appeal("CLM-2024-00123", "HUMANA", "test letter")`; assert `confirmation_number` starts with `"CONF-HUM-"` and `submitted_at` is non-empty.
